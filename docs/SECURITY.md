# Security Architecture & Threat Model — Orivanta PIM

## 1. Application-Layer Multi-Tenant Isolation

### 1.1 The SQLite Architectural Reality
SQLite is an embedded, single-file relational database engine. Unlike enterprise client-server databases such as PostgreSQL, **SQLite does not support native database-level Row Level Security (RLS)**.

To provide genuine multi-tenant isolation, Orivanta PIM implements the **Context-Enforced Repository Pattern**:
- Every authenticated API request resolves an immutable `WorkspaceContext { userId, workspaceId, role }` through middleware (`backend/src/middleware/tenant.ts`).
- All repository and service queries explicitly append `and(eq(table.id, id), eq(table.workspaceId, ctx.workspaceId))` to every `SELECT`, `UPDATE`, and `DELETE` operation.
- Negative authorization integration tests continuously verify that attempts to access or mutate records belonging to other workspaces return `404 Not Found` or `403 Forbidden`.
- Query execution never reveals whether an out-of-scope record exists in another workspace, mitigating cross-tenant user/product enumeration.

## 2. Authentication & Session Security
- **Password Storage**: Passwords are never stored in plaintext. Hashing is performed using **Argon2id** (`m=65536, t=3, p=4`), the winning algorithm of the Password Hashing Competition.
- **Session Tokens**: Cryptographically secure 256-bit random tokens stored in SQLite with explicit expiration dates.
- **Cookie Security**: Delivered via `httpOnly`, `sameSite: 'lax'`, and configurable `secure` cookies to protect against XSS token theft.
- **Session Rotation & Invalidation**: Tokens are deleted from SQLite upon explicit logout.

---

## 3. Secret Redaction & Log Hygiene
- Sensitive keys (`password`, `password_hash`, `session_secret`, `consumer_secret`, `gemini_api_key`) are dynamically masked by the request logging middleware.
- Full credential-bearing URLs and WooCommerce keys are never logged to standard output or persisted in sync job payloads.
- Client bundles produced by Vite contain zero backend secrets.

---

## 4. Agentic AI Safety & Human Approval Boundaries
- **Advisory Default**: The Gemini Agent tool registry contains zero database mutation tools and zero external publishing tools.
- **Bounded Loop**: The tool execution loop enforces a strict limit of 6 tool turns per request (`AI_MAX_TOOL_STEPS=6`) and a 30-second timeout.
- **Zod Argument Sanitization**: All tool inputs generated by LLM reasoning are strictly validated using Zod schemas before tool execution.
- **Prompt Injection Defense**: User notes and imported catalogue descriptions are treated as untrusted data and delimited in system prompts.
- **Human Review**: AI-generated content can only be committed to the database through an explicit operator confirmation button in the UI.
